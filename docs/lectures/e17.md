# E17 反脆弱设计

> 本讲关键词：波动 · 备胎收入 · 系统冗余

反脆弱不是不会受伤，是**波动来的时候，你的系统能变得更强。** 平台限流、模型降价、客户延期、身体生病，都会发生。OPC 如果只有一条收入管道，任何一个波动都能把你打回雇员市场。

产品经理做架构时会考虑单点故障。给自己的公司做架构时，也要找单点：某一个平台、某一个大客户、某一种技能、某一段身体状态。

## 四个单点，逐个拆

1. **渠道单点**：只在一个平台获客。限流那天，漏斗归零。
2. **客户单点**：一个客户超过收入 40%。他一走，你的定价权也走。
3. **产品单点**：只会卖一种必须你实时在场的服务。
4. **身体单点**：只有你能交付，也没有文档。

拆单点的方法不是立刻做十件事，而是给每个单点加一条备胎：

- 渠道：主场 + 私域名单（名单是你真正拥有的渠道）
- 客户：任何新客户进来，都要能被产品复制，而不是被你特供
- 产品：服务旁边一定有信息产品或模板
- 身体：交付 SOP 写到别人能临时代班的程度，即使暂时没人代班

## 让波动变成养料

反脆弱的关键是：每次出事，都留下比出事之前更强的资产。

- 被拒：留下拒绝原因，改卖点和价格
- 交付翻车：留下检查表，下次不再犯
- 平台不行：留下可迁移的内容库和名单
- 大客户离开：留下可公开的方法论，而不是只留下依赖

如果你在波动里只感到消耗，没有留下新资产，说明系统还是脆弱的。脆弱系统靠意志力硬扛；反脆弱系统靠复盘变现。

## 本讲作业

写一份“停摆 14 天预案”：

- 哪部分收入会立刻断
- 哪部分内容还能自动被看到
- 哪部分客户能自我服务
- 你回来后第一件要做的事是什么

预案写得出来，说明系统开始有冗余；写不出来，就从名单备份和交付文档做起。
